# REPKIT Hold from (spec revision 34) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Counter hold is either **At** (one value, today's hold) or **From** (every value from N up to the cap, each held for the hold's count), chosen per hold on the Progression page and stored as `60+:2` in `entry.holds`.

**Architecture:**
- **Domain (pure, test-first):** `Hold` gains `kind: HoldKind = HoldKind.AT`. `ProgressionConfig.activeHold(total)` picks the most specific hold: an exact active At, else the active From with the greatest `at ≤ total < cap`. `RepProgression` and `holdResetNeeded` need no code change, only new tests. `SettingsValidator` keys duplicates by `(kind, at)`.
- **Data:** `HoldsCodec` writes a From item as `at+:for`; `storedHolds` repairs with `distinctBy { kind to at }`. No Room version change.
- **UI:** each hold row gets an At | From segmented choice under "Hold N"; the value row's label, ⓘ, spoken name and tags follow it. The hold announcement names the total instead of `hold.at`.

**Tech Stack:** Kotlin, Compose Material 3, Hilt, Room 2.8.1 (unchanged schema v7), JUnit 4, Robolectric (`@Config(sdk = [34])`). No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-09-hold-from-design.md` (revision 34). It amends `docs/superpowers/specs/2026-10-01-multi-hold-design.md` (revision 16) §2–§6 and `docs/superpowers/specs/2026-10-02-hold-highlight-design.md` (revision 20) §2. Read both, and `claude.md`. ## Plan notes (decisions made while reading the real code)

Task 7 appends these to the spec as §11.

1. **A From hold's "inactive" hint is always "Hold disabled".** Revision 28's bound-naming hints read "Hold at N is above the maximum (M)", which would misname a From hold, and §7 adds no From version. §3 already says a From hold at or above the cap gets "the hint". So `holdHint` returns `HoldDisabled` for any inactive From hold (above the cap, at the cap, below the floor, or a count of 0); At holds keep revision 28's hints.
2. **Test tags.** `StepperRow` derives its tags from the spoken name, so a From value row is `value_Hold 1 from` / `support_Hold 1 from` / `card_Hold 1 from` (spoken name from `hold_n_from`). The segments are tagged with the hold's 1-based number: `hold_1_kind_at`, `hold_1_kind_from` (§5's `hold_n_kind_at`).
3. **Codec strictness.** `at` must be plain digits with at most one trailing `+`. Kotlin's `toIntOrNull` used to accept a leading `+`, so `"+64:4"` read as at 64; it is now malformed and dropped. No build ever wrote it.
4. **`newHold` is unchanged.** "+ Add hold" makes an At hold (§5) and still avoids every existing `at`, whatever its kind. An At on a From's value is valid, so this is only a little more conservative.
5. **`HoldStatus.at` keeps its name** and now carries the total (§6). For an At hold the two are equal.
6. **Saved state.** The draft's holds are saved as `(at, forCount, kind.ordinal)` triples under the same key.
7. **Tapping the segment that is already selected does nothing** (no edit, no save).

and replace `activeHold`:

```kotlin
    /**
     * The hold at [total], or null (spec rev 34 §2, the most specific wins): the active At hold on
     * [total] (the first, for duplicates the validator rejects); otherwise the active From hold with
     * the greatest start at or below [total]. A From hold covers start..<cap, so the cap never holds.
     */
    fun activeHold(total: Int): Hold? =
        holds.firstOrNull { it.kind == HoldKind.AT && it.at == total && isActive(it) }
            ?: holds.filter { it.kind == HoldKind.FROM && it.at <= total && total < cap && isActive(it) }.maxByOrNull { it.at }
```

```kotlin
            if (i !in holdErrors && !c.isActive(h)) holdHints[i] = holdHint(h, c)
        }
        return ValidationResult(e, holdErrors = holdErrors, holdHints = holdHints)
    }

    private fun duplicate(h: Hold): FieldMessage = when (h.kind) {
        HoldKind.AT -> FieldMessage.DuplicateHold(h.at)
        HoldKind.FROM -> FieldMessage.DuplicateHoldFrom(h.at)
    }

    /**
     * Why an inactive hold is inactive (spec revision 28 rule 6): outside floor..cap first, then the
     * plain hint. A From hold always gets the plain hint (plan note 1, spec rev 34 §3).
     */
    private fun holdHint(h: Hold, c: ProgressionConfig): FieldMessage = when {
        h.kind == HoldKind.FROM -> FieldMessage.HoldDisabled
        h.at > c.cap -> FieldMessage.HoldOutsideRange(h.at, c.cap, isAbove = true)
        h.at < c.floor -> FieldMessage.HoldOutsideRange(h.at, c.floor, isAbove = false)
        else -> FieldMessage.HoldDisabled
    }
```

```kotlin
import com.mitenko.repkit.domain.model.Hold
import com.mitenko.repkit.domain.model.HoldKind

/**
 * The `entry.holds` column (spec rev 16 §5, rev 34 §4): `"56:3,60+:2"` in list order (an At hold
 * `at:for`, a From hold `at+:for`), `"-"` for an empty list. The empty string is the column default
 * and is never written, so it stays free to mean "not yet written by v5 code" (EntryMapping then
 * reads the legacy hold_at / hold_for).
 */
internal object HoldsCodec {
    private const val EMPTY = "-"
    private const val FROM_MARK = "+"

    /** `at` is plain digits, optionally followed by one `+` for a From hold (plan note 3). */
    private val AT_PART = Regex("""(\d+)(\+?)""")

    fun encode(holds: List<Hold>): String =
        if (holds.isEmpty()) EMPTY else holds.joinToString(",") { "${it.at}${if (it.kind == HoldKind.FROM) FROM_MARK else ""}:${it.forCount}" }

    /**
     * Item by item: a malformed item, or one with at < 1 or forCount < 0, is dropped and the rest are
     * kept in order. Null when no item survives (including `""`), unless [text] is the empty-list `"-"`.
     */
    fun decode(text: String): List<Hold>? {
        if (text == EMPTY) return emptyList()
        return text.split(",").mapNotNull(::decodeItem).ifEmpty { null }
    }

    private fun decodeItem(item: String): Hold? {
        val parts = item.split(":")
        if (parts.size != 2) return null
        val match = AT_PART.matchEntire(parts[0]) ?: return null
        val at = match.groupValues[1].toIntOrNull()?.takeIf { it >= 1 } ?: return null
        val forCount = parts[1].toIntOrNull()?.takeIf { it >= 0 } ?: return null
        val kind = if (match.groupValues[2].isEmpty()) HoldKind.AT else HoldKind.FROM
        return Hold(at, forCount, kind)
    }
}
```
